# Browser extension authentication for self-hosted Serial

The official Serial extension connects to hosted and self-hosted instances
without extension-specific credentials or configuration. Keep the instance on
the latest database migration, set its public origin correctly, and serve it
over trusted HTTPS. The extension handles the rest through the **Connect
extension** flow.

## Deployment requirements

- Run the latest Serial database migrations. Extension connections require the
  `extension_session` table.
- Set `PUBLIC_BASE_URL` to the browser-facing origin where users open Serial.
- Use HTTPS with a browser-trusted certificate. Plain HTTP is supported only on
  `localhost`, `127.0.0.1`, and `[::1]` for local development.
- Complete Serial's initial account setup before connecting the extension.

For a typical self-hosted instance:

```env
PUBLIC_BASE_URL=https://serial.example.com
```

Use an origin only: do not include a path, query string, or fragment. TLS may
terminate at a reverse proxy as long as the browser-facing origin uses HTTPS.

If users can open the same deployment through additional origins, add those
origins to the existing comma-separated `TRUSTED_ORIGINS` setting. The
connection approval page rejects requests from origins Serial does not trust.

No OAuth client ID, client secret, discovery endpoint, refresh-token setting,
or proxy-hop setting is required.

## Connect the extension

1. Open the Serial extension.
2. Select the detected Serial instance, a previously used instance, the hosted
   Serial default, or enter a self-hosted address.
3. Grant the extension access to that instance when the browser asks.
4. Sign in to Serial in the browser, if needed.
5. Review the approval page and select **Connect extension**.

The extension defaults to `https://app.serial.tube`. When it is opened from a
Serial tab, it can detect that tab's origin and offer it as the first choice.
Users can always select **Choose another instance** and enter a different
self-hosted origin.

Remote plain-HTTP origins such as `http://192.168.1.50:3000` are intentionally
rejected. Put trusted HTTPS in front of the service or use an encrypted tunnel
that exposes the service through a loopback address.

## Local development

Loopback HTTP works without a certificate:

```env
PUBLIC_BASE_URL=http://localhost:3000
```

Use the same origin in the extension. A different local hostname is treated as
a remote instance and must use trusted HTTPS.

## Custom extension builds

Serial already allows the identity redirect addresses used by the official
Chrome and Firefox builds. Nothing needs to be configured for those builds.

A development or independently packaged extension can have a different
redirect address from `browser.identity.getRedirectURL()`. Add that exact
address to `SERIAL_EXTENSION_REDIRECT_URIS`:

```env
SERIAL_EXTENSION_REDIRECT_URIS=https://extension-id.chromiumapp.org/serial-auth
```

Separate multiple addresses with commas. Serial accepts only HTTPS identity
redirects generated by Chromium or Firefox, and validates each address exactly.
Wildcards, credentials, ports, query strings, fragments, and paths other than
`/serial-auth` are rejected.

## Connection and session security

The connect flow uses an explicit approval page and the browser's identity API.
It does not turn Serial into a general-purpose OAuth provider.

- The extension creates a random state value and a PKCE S256 verifier for each
  attempt.
- After approval, Serial issues a one-time connection grant that expires after
  two minutes.
- The extension exchanges that grant for one opaque session token. The grant
  is consumed atomically and cannot be replayed.
- Extension sessions expire after 30 days and are not refreshed. The user must
  reconnect after expiration.
- The browser stores the session token locally. Serial stores only its SHA-256
  hash in the database.
- **Sign out of extension** revokes the server-side session and removes the
  extension's permission for that instance.
- Deleting an account deletes its extension sessions. A missing or actively
  banned account is also rejected when the extension checks its session.

Treat an extension session token like any other bearer credential. Do not log
it, place it in a URL, or copy it between browsers.

## Capture and outbound-request security

The extension normally extracts readable content inside the active tab and
sends only that bounded, sanitized capture. If the extension cannot produce a
usable capture, Serial may fetch the public page once as a server-side fallback.
Serial also performs bounded Feed discovery when the page declares no Feed.

Both paths accept only public HTTP or HTTPS destinations on their standard
ports. Serial resolves and validates every address, pins the request to the
validated address, and repeats validation after every redirect. Private,
loopback, link-local, multicast, credential-bearing, nonstandard-port, and
non-HTTP destinations are rejected. Response size, header size, redirect count,
DOM size, duration, candidate count, and worker concurrency are bounded.

`SERIAL_CAPTURE_MAX_CONCURRENT_FETCHES` controls the instance-wide number of
simultaneous server-side Bookmark capture and discovery fetches. It defaults to
`8` and must be a positive integer. Lower it on a resource-constrained instance;
requests above the available capacity fail fast while the Bookmark write itself
remains independent of optional Feed discovery.

Reverse proxies should preserve streaming request bodies instead of buffering
unbounded uploads, and should not rewrite rejected destinations through an
internal proxy. No private-network access is required for capture.

## Remote media privacy

Serial displays Feed artwork, article images, and Bookmark preview images from
their original hosts. The browser sends no HTTP referrer and defers image loads
until needed, but it still connects directly to those third-party hosts. Those
hosts can therefore observe the user's IP address and the time of the request.

A privacy-preserving image proxy is planned for a future release. Until it is
available, operators with stricter privacy requirements should account for
direct third-party image requests in their deployment and user guidance.

## Troubleshooting

### The instance is rejected before the browser opens Serial

Confirm the address is an origin and uses trusted HTTPS. Only the three
loopback hosts listed above may use HTTP.

### The approval page says the origin is not trusted

Confirm `PUBLIC_BASE_URL` exactly matches the origin in the browser. If the
deployment intentionally supports another origin, add it to `TRUSTED_ORIGINS`
and restart the app.

### The extension reports an incompatible or non-JSON response

Confirm the selected address points to a current Serial deployment, not a
reverse-proxy error page or an older version. Run the latest application and
database migrations together.

### A custom build cannot complete the redirect

Read the exact value returned by `browser.identity.getRedirectURL("serial-auth")`
in that build and add it to `SERIAL_EXTENSION_REDIRECT_URIS`. Restart Serial
after changing the environment.

### The connection expired

Open the extension and connect again. Sessions have a fixed 30-day lifetime;
there is no refresh token to recover or rotate.

Do not bypass certificate warnings or disable TLS verification. Fix the public
origin or certificate instead.
